## Notes

### Blind
```html
<label for="name-input">Name</label>
<input id="name-input" type="text"/>
```

```html
<input aria-label="Name" type="text"/>
```

in chrome dev tools `ctrl+shift+p` > `show accessibility` > `Enable full-page accessibility tree`

* [Accessible Rich Internet Applications (ARIA)](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA)

**For toast messages, pop ups use `aria-live`**
```html
<div aria-live=""></div>
```
Has 3 options: `off`, `assertive`, `polite`, generally `polite` is used, it waits for the current action to be completed by the accessibility tool, `assertive` interrupts

### Color blind
* Go to styles section of dev tools
* check `contrast ratio`, hit minimum `AA` if not `AAA`, higher `contrast ratio` the better
* `ctrl+shift+p` > `show rendering`, can emulate different conditions (`Emulate Visual Deficiencies`)
* for dark theme generally don't opt for solid black, very high contrast can be straining, opt more gray
* test website when high contrast mode of OS enabled

### General visual
* `alt` tag in `<img>`, describe the image
* Use semantic HTML, eg `<nav>` for navigation bar, `<aside>` for side content, page wrapped in `<main>`, headings `<h1>`,...`<h6>`, etc (1 `<h1>` per page generally, don't use it for making text bigger and only use for page hierarchy), `<header>` for header, `<section>` for section, `<article>` for article, if you want a button add a button `<button>` not `onclick` event listener
* text in `<a>text</a>` should describe what the link does, not just "click me"
* make sure site works properly on zooming
* test site with screen reader
* maybe ask someone who actually uses a screen reader on a dialy basis to test your website out

### Keyboard
* tab is used for navigation
* `tabindex`, positive number puts high priority to that element, only 0 and -1 are acceptable values for `tabindex`
* adding `tabindex="0"` to an element makes it tabbable, use sparingly to only custom made JS elements to replace something like `<select>`
* `tabindex="-1"` doesn't make something tabbable but allows writing JS to focus on that element (programmatically focusable but not user focusable)
* `tabindex="0"` can be used for scrolling, if there's overflow and we tab to that element we can scroll using keyboard arrows
* don't remove outline, if you remove outline then add something like `focus-visible` CSS property
* If you do anything that removes default accessibility features then remember to add a proper replacement
* try to use your website with just keyboard and no mouse
* implement **skip links** if you have too many links, allows user to skip to main content

### Hearing based
* captions for audio/video
* make captions searchable if possible
* add description below video/audio explaining what it is
* contact should not be just calling, some way to write to you too/not involving listening
* test if it works with sound turned off

### Motor function
* clickable elements are spaced out far enough
* clickable area should be big enough
* label can help with clickability
* avoid timing based clicking
* `@media (prefers-reduced-motion) {}` (or something like that) use these to for animations and all
* give option to switch to dyslexic friendly font
* use `autofocus` correctly to focus important element whenever a page loads

### General
* mobile friendly, set up `<meta>` `viewport` set up properly

### Testing
* **Lighthouse**
* `eslint-plugin-jsx-a11y` or similar
* `chrome://accessibility` for advanced, more for people who implement screen reader tech
